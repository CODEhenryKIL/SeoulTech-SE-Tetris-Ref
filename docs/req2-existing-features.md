# 요구사항 2 기존 기능의 규칙과 수용 검사

범위는 R2-09(난이도), R2-11(L 아이템·행 삭제), R2-12(무게추)다. PR #17의 오류 수정이 main `dbb8968`에 병합된 상태에서 이어서 검증한다. 원본 R2-01~06은 PR #15 작업 이력으로 보존하며, 이 문서의 결과는 보완 카드에 연결한다. 신규 자체 아이템·전체 공급 흐름·모드별 기록·최종 대상 OS 수동 검증은 각각 R2-08/13·10·14·07에서 계속 진행한다.

## 난이도 (R2-09)

- 기본 설정은 Easy다. Classic과 Item 모두 게임 생성 시 난이도를 확정하며, 이후 설정 변경은 진행 중인 게임의 난이도를 바꾸지 않는다. 각 게임의 보드·점수도 독립적이다.
- Normal은 기존 7종 동일 확률과 레벨별 속도 공식을 유지한다. Easy/Hard에서 바꾸는 것은 I 블록의 상대 가중치와 속도 증가량이다.
- 난이도에 따른 추가 점수 배율이나 별도 규칙은 도입하지 않는다. 모든 난이도에서 실제 낙하 한 칸당 현재 레벨 점수, 일반 행 삭제의 100·200·300… 콤보 규칙을 유지한다.
- 속도 공식·반올림 예시는 [요구사항 검사 기준](test-requirements.md#난이도별-속도-계산-기준)을 따른다. 모든 난이도의 최초 간격은 1,000ms이고 레벨은 1~19, 간격은 최소 1ms다. Normal의 기존 공식과 레벨 상한을 보존한다.

### 실제 생성기의 분포 판정

별도 추첨 구현 대신 게임이 사용하는 `BlockGenerator.nextBlock(Difficulty)`를 직접 호출한다. 고정 seed와 난이도별 100,000회 표본으로 CI에서 같은 실험을 재현한다. 추첨 1,000회 이상이라는 원문 조건을 충족하며, 큰 표본으로 우연한 통계 실패를 줄인다.

| 난이도 | I 가중치 / 전체 | I 기대 확률 | 나머지 6종 각각 기대 확률 |
|---|---|---|---|
| Easy | 12 / 72 | 16.6667% | 13.8889% |
| Normal | 10 / 70 | 14.2857% | 14.2857% |
| Hard | 8 / 68 | 11.7647% | 14.7059% |

원문 5쪽의 ±5%는 팀 검증 기준으로 **각 블록의 기대 확률 대비 상대오차 5% 이내**를 적용한다. `abs(실제 비율 − 기대 비율) / 기대 비율 <= 0.05`로 계산한다. 절대 비율의 ±5%p보다 엄격한 기준이며, 두 해석 모두 통과하도록 한다. 통과할 때까지 seed를 바꾸거나 반복 실행 중 성공한 표본만 선택하지 않는다. 평가자가 다른 판정식을 제시하면 기존 수치와 seed를 보존하고 비교 결과를 추가한다.

`build/reports/req2/block-distribution.csv`에 seed·표본·각 블록 수·기대/실제 비율·상대오차를 기록한다. CI의 `test-reports-<OS>` 아티팩트에 이 폴더도 포함한다. `DifficultyAcceptanceTest`의 전 레벨 규칙, 기존 `DifficultyUiTest`의 키보드 선택·저장/복원·초기화와 게임별 상태 독립 검사를 함께 사용한다.

## L 아이템과 일반 행 삭제 (R2-11)

- 기본 7종의 점유 칸 4곳 중 하나에 L을 붙인다. 이동·회전 시 표식과 효과 좌표가 같은 실제 칸을 가리킨다. 기존 `RowBlockTest`가 7종 × 4곳 × 4회전의 112개 상태를 검사한다.
- 블록 고정 시 L이 있는 행은 가득 차지 않아도 삭제한다. 같은 고정에서 완성된 일반 행과 L 행을 먼저 합친 다음, 행 번호를 중복 제거하고 한 번에 아래로 압축한다. 위쪽에는 빈 행을 보충하고 화면 문자도 같은 방식으로 옮긴다.
- 삭제 행 수에 따라 100·200·300…을 한 번씩 가산하고 모든 행을 누계에 포함한다. 동일 행이 일반 완성과 L 효과에 모두 해당해도 한 번만 계산한다. 10줄 경계에서 레벨·공급 판정으로 전달한다.
- 일반 행 삭제는 격자를 즉시 갱신하고 원래 행 위치에 210ms 동안 흰 반투명 강조를 표시한다. 30ms 타이머로 종료를 확인하므로 실제 표시 시간은 이벤트 큐 상황에 따라 약간 길어질 수 있다. 이동·낙하는 계속 가능하다.
- L 효과는 중앙에서 양끝으로 50ms 간격의 5단계 지우기를 표시하고 다음 종료 tick에서 효과를 끝낸다(통상 약 300ms, EDT 부하에 따라 지연 가능). 열 아이템과 타이머 상태 처리를 공유한다.
- 아이템 효과 동안 이동·회전·자동/수동 낙하·하드드롭을 차단한다. 일시정지·재개와 메뉴 복귀는 허용한다. 정지는 효과가 끝나도 유지되며, 효과 중 재개를 요청하면 종료 후에만 낙하한다. 메뉴 복귀 시 효과를 취소해 이전 게임의 점수·다음 블록 처리를 중단한다.
- Normal·Protanopia·Deuteranopia·Tritanopia에서 L 문자와 삭제 강조가 보이도록 한다. 문자·형태와 렌더링 픽셀 차이를 자동 확인하되 실제 사용자의 색 구분·물리 키 조작 검증은 R2-07에서 유지한다.

`LineItemAcceptanceTest`는 미완성 행·최상단·최하단·비연속 여러 행과 표시 경계를 검사한다. 중복 점수·누계·회전·정지/재개·메뉴 취소는 `RowBlockTest`와 `Pr15BoardRegressionTest`의 결과를 재사용한다. 전체 아이템 공급 경계 검증은 R2-10이다.

## 무게추 (R2-12)

- 기존 너비 4칸·높이 2칸의 ` OO ` / `OOOO` 모양과 O 문자를 유지한다. L·C·B 효과 문자와 구별하고, 기본 블록과는 6칸 형상 및 회색 표시로 구분한다. 네 팔레트에서도 문자·형상과 배경 대비를 유지한다.
- 각 팔레트의 실제 보드 이미지에서 점유 칸마다 배경과 RGB 채널 차이가 80 이상인 픽셀이 5개 이상인지 검사하고 PNG를 보관한다. 이는 거의 검은색으로 표시되는 퇴행을 잡는 자동 기준이며 사람의 접근성 평가나 WCAG 적합성을 증명하지 않는다.
- 최초 접촉 전에는 좌우 이동할 수 있다. 바닥이나 다른 블록에 처음 닿은 뒤에는 접촉 상태를 기억하여 옆으로 이동하지 못하며, 장애물이 나중에 없어져도 풀리지 않는다. 무게추는 회전하지 않고 회전 위치 보정도 적용하지 않는다.
- 고정 시 현재 무게추 바로 아래의 폭 4칸 영역을 바닥까지 지운 뒤 바닥에 배치한다. 영역 밖과 무게추 위의 블록은 유지한다. 효과가 끝나면 미리보기의 블록이 실제 현재 블록이 되고 다음 블록에서 접촉 잠금을 초기화한다.
- 점수 정책: **아이템 발동·제거한 블록·효과에 의한 강제 바닥 이동은 0점**이다. 효과 전 실제 자동/수동/하드드롭 이동에는 요구사항 1의 `이동 칸 수 × 현재 레벨` 점수를 유지한다. 이 낙하 점수는 원문 9쪽에서 허용한 추가 점수 정책이며, 삭제 블록 개수에 따른 보너스는 없다. 일반 완성 행이 있으면 공통 행 삭제 규칙을 별도로 적용한다.

`AnchorAcceptanceTest`는 형상·문자·색각 팔레트, 양쪽 벽에서 제거 범위 안/밖과 위쪽 보존, 강제 이동 무점수, 높이가 다른 장애물 접촉 후 실제 다음 블록 승계를 검사한다. 접촉 전후 이동·반복 회전·접촉 상태 유지/초기화는 `Pr15BoardRegressionTest`를 재사용한다.

## 실행과 결과

```bash
./gradlew --no-daemon --console=plain build desktopSmoke
```

JUnit XML/HTML, 전체 제품 JaCoCo 보고서와 위 분포 CSV를 함께 확인한다. 전체 제품 코드 coverage 70% 기준과 기존 55개 독립 회귀 검사는 변경하지 않는다. 최종 실행 결과는 [검증 기록](verification.md)에 남긴다. 이 범위의 통과는 신규 아이템·모드별 저장이나 요구사항 2 전체 완료를 의미하지 않는다.
