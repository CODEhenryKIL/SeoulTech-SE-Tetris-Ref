# 1차 요구사항 추적표

교수님 요구사항이 어떤 작업 카드에 연결되는지 확인하는 표입니다.

- 기준 자료: `TeamProject_Req1.pdf` (19쪽, 페이지 번호는 PDF 기준)
- 작성: 길민규 / 2026-09-21
- 문서 상태: 팀원 검토 대기 (`SETUP-07`, Review)
- [작업 칸반보드](https://github.com/users/HoroyoiPeach/projects/3)
- 이 표의 `R` 번호는 찾기 쉽게 붙인 팀 내부 번호이며 교수님이 부여한 번호가 아닙니다.

## 읽는 방법

1. 교수님 요구사항과 아래 설명이 같은 뜻인지 확인합니다.
2. 연결된 카드가 그 내용을 빠짐없이 맡고 있는지 확인합니다. 보드에서 `CORE-01`처럼 카드 번호를 검색하면 됩니다.
3. 구현 후에는 해당 카드 본문에 코드·PR·테스트 결과 링크를 남깁니다.

**이 표는 요구사항과 작업을 연결한 문서입니다. 표가 완성됐다는 것이 게임 기능까지 구현·검증됐다는 뜻은 아닙니다.** 실제 담당자와 진행 상태는 칸반에서 관리하고, 중간 점검부터 최종 제출까지의 증빙은 `PM-05`에서 한 원장으로 정리합니다.

## 5. 해석과 팀 결정

- PDF 1쪽은 표지, 3·4쪽은 기능·비기능 요구사항의 개요입니다. 세부 항목은 위 표에 연결했습니다. 10쪽의 통계·참고 링크는 설계 참고 자료이며 별도 구현 기능이 아닙니다.
- 교수님은 OS 하나만 지원해도 된다고 했지만, 팀은 **Windows 11과 macOS 26 이상 모두 지원**하기로 결정했습니다. `SETUP-02`의 완료는 지원 대상 결정 완료이며, 두 OS의 실행 검증은 `RELEASE-04`에서 진행합니다.
- 18쪽은 Java 21 이상 및 경로 설정이 이미 되어 있다고 가정해도 되고, `JAVA_HOME`을 사용하거나 Java 실행 환경을 패키지에 포함해도 된다고 안내합니다. 실제 배포 방식 결정과 실행 패키지 생성은 `RELEASE-03`에서 함께 다룹니다. 팀 보유 기기를 활용합니다.
- 17쪽의 커버리지 표현은 '50-70% 이상'입니다. 50%만으로 최종 통과를 보장하지 않습니다. 팀 목표를 70% 이상으로 제안하며, 정확한 평가 기준이 필요하면 e-class에 확인합니다.
- 아직 결정할 것: 참고 코드 활용 범위, 속도 증가 기준, 점수 계산식, 동점 처리, 다음 블록 표시 개수, 화면 크기 3종, 기본 키와 중복 키 처리, 저장·배포 방식. 결정 후 `PM-02`와 관련 카드에 기록합니다.
- 행 삭제 후 위 블록 이동, 경계·고정 블록 충돌 등 정상 게임 진행에 필요한 동작은 암시적 요구사항으로 분류했습니다. 추가로 발견하는 조건은 이 표와 카드에 함께 반영합니다.
