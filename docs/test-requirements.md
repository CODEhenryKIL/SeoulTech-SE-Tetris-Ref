# TEST-04·05 요구사항 검증

누적 기능의 최종 검사 버전·양 OS CI·패키지 증빙·수동 대기 조건은 [R2-07 최종 검증 원장](req2-final-verification.md)에 통합한다. 아래 과거 범위의 기록과 현재 최종 결과를 구분한다.

R2-08·10·13의 다섯 아이템 명세·공급 정책과 경계 검사는 [아이템 규칙과 공급 검증](req2-items.md)을 따른다. C/B 효과 자체의 점수는 0, P의 두 행은 기본 300점이며 실제 낙하와 일반 완성 행 점수는 별도 유지한다.

R2-14의 모드별 저장·순위 진입·필터·이전 파일 호환 정책 및 검사 연결은 [모드별 기록 정책과 검증](req2-mode-scores.md)을 따른다. 아래의 과거 검증 기록은 각각 당시 범위이며, 현재 새 게임은 난이도와 모드를 포함하는 4필드 형식으로 저장한다.

요구사항 1의 회귀 기반은 `docs/req1-nondev-tasks`에서 구성했다. 기존 55개 독립 회귀 검사의 이름과 기대값은 제품 요구에 맞춰 갱신하며, 중복되지 않는 시간·속도·점수 경계 검사 3개를 JUnit에 추가했다. 아래 BUG-03 후속 검사는 `fix/pr15-req2-bugs`의 변경 기준이다.

### 난이도별 속도 계산 기준

요구사항 2 원문 3쪽의 “속도 증가량”을 기준으로 한다. Normal의 기존 레벨별 간격을 `d`초라 할 때 Normal 속도는 `1/d`칸/초다. 세 난이도의 초기 속도는 모두 1칸/초이며, 이후 속도는 `1 + 계수 × (1/d − 1)`이다. 계수는 Easy 0.8, Normal 1.0, Hard 1.2다. 즉 같은 레벨 변화의 속도 증가량을 Normal 대비 20% 줄이거나 늘리며, 타이머 간격을 단순히 ±20% 바꾸지 않는다.

| 레벨 | Easy 간격 | Normal 간격 | Hard 간격 |
|---|---|---|---|
| 1 | 1000ms | 1000ms | 1000ms |
| 2 | 827ms | 793ms | 761ms |
| 3 | 669ms | 618ms | 574ms |

밀리초 단위로 반올림하고 최소 1ms·레벨 19 상한을 유지한다. 따라서 가장 빠른 구간에서는 정수 Timer 간격이 같아질 수 있다. 낙하 입력별 칸당 점수와 기존 Normal 규칙은 유지한다.


## 통합 중 발견·수정한 결함과 명시적 기대값 변경

R2-09·11·12의 추가 정책·확률 판정·아이템 경계 수용 검사는 [기존 기능 규칙과 수용 검사](req2-existing-features.md)에 기록한다. PR #17 검사를 재사용하며 난이도별 실제 생성기 분포와 L/무게추의 남은 경계를 보강한다.

- R24: 자동·수동·하드드롭 기본 낙하 점수를 칸당 1로 통일. R25: 같은 거리에서 현재 레벨만큼 가산(기본 1 + 레벨−1). 기존 `hard-drop`·`drop-input-score` 기대값은 이 요구 결함 수정에 맞춰 변경했으며 동작 차이를 숨기기 위한 변경이 아니다.
- RANK-05: 새 게임 기록에 `이름:점수:난이도`를 저장하고 난이도를 표시한다. 기존 2필드 기록은 그대로 읽고 2인자 저장 API도 유지한다. `score-append-bytes`·`score-refresh` 기대값에 신규 기록의 Normal 메타데이터/표시를 반영한다.
- TEST-05: 마지막 줄바꿈이 없는 기존 파일에 새 점수를 붙이면 두 기록이 합쳐져 사라지던 결함을 수정했다. 기존 바이트를 지우지 않고 구분 줄바꿈을 보충하며 기존·신규 기록이 모두 남는지 검사한다.
- TEST-06: 게임 진행 중 Esc로 메뉴 복귀, 이름 입력 후 실제 점수판 표시와 새 점수 강조를 연결한다. 합성 KeyListener 이벤트의 실제 JFrame 검사와 OS의 물리 입력 검증은 구분한다.
